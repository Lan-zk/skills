# writing-to-card 设计文档

**日期**：2026-04-08
**状态**：已确认

---

## 1. 目标

将长篇 Markdown 文章自动转换为多张 1080×1440 PNG 图片，适合小红书（小红书）平台发布。解决该平台不支持长图文发布的痛点。

---

## 2. 技术栈

| 组件 | 选型 | 说明 |
|------|------|------|
| 渲染引擎 | Playwright | 与 github-trending-to-card 一致 |
| Markdown 解析 | markdown-it | 直接输出 HTML，注入 Handlebars 模板 |
| 模板引擎 | Handlebars | `{{content}}` 占位符注入 HTML 片段 |
| 截图 | Playwright `screenshot()` | 对 `.page-container` 元素截图，deviceScaleFactor: 2 |

---

## 3. 画布与排版规范

### 3.1 画布尺寸

- 宽度：1080px，高度：1440px（3:4 比例）
- Viewport 配置：`1080 × 1440`，`deviceScaleFactor: 2`（实际渲染 2160 × 2880 视网膜分辨率）

### 3.2 字体规范

- 字体族：`"Songti SC", "SimSun", "Times New Roman", serif`
- 正文字号：44px
- 行高：1.8
- 标题字号：封面标题 120px，加粗；正文内 h1 72px，h2 56px

### 3.3 正文排版

- 左右留白：120px（有效阅读宽度 840px）
- 段落间距（下边距）：40px
- 列表缩进：0px，顶格排版

---

## 4. 模板系统

### 4.1 架构原则

支持多套模板可切换（MVP 先实现一套默认模板），模板之间通过名称切换。

### 4.2 封面模板（cover）

布局从上到下：
1. **标题区**：主标题，120px，加粗，居中
2. **分割线**：水平细线，宽度 200px，颜色 `#e8453c`
3. **副标题区**：用户传入的副标题，36px，颜色 `#666666`

封面底部（固定）：
- 日期：动态，格式 `YYYY-MM-DD`
- 署名：固定文字（如"写作卡片"）

背景色：模板可自定义（MVP 默认米白 `#faf9f7`）

### 4.3 正文模板（content）

- 背景色：`#faf9f7`（米白）
- 正文颜色：`#1a1a1a`（深灰）
- 强调色：`#e8453c`（红色，用于分割线、引用块左边线等）
- 引用块：左侧 4px 红色边线，内边距左 24px

---

## 5. Markdown 支持范围

| 元素 | 支持 | 说明 |
|------|------|------|
| 普通段落 | ✓ | 基础文本块 |
| 一级标题（h1） | ✓ | 72px，加粗 |
| 二级标题（h2） | ✓ | 56px，加粗 |
| 加粗 | ✓ | `**text**` 或 `__text__` |
| 斜体 | ✓ | `*text*` 或 `_text_` |
| 行内代码 | ✓ | 反引号包裹 |
| 无序列表 | ✓ | 列表项顶格，段落间距 40px |
| 有序列表 | ✓ | 同上 |
| 引用块 | ✓ | 左侧红色边线 |
| 本地图片 | ✓ | 行内显示，路径相对于输入文件目录 |

**不处理**：链接（渲染为纯文本）、图片链接、代码块（代码块独占一页暂不实现）、表格（暂不实现）、删除线。

---

## 6. 图片处理

### 6.1 路径解析规则

Markdown 中的图片路径为相对路径，相对于输入文件所在目录解析。

```markdown
![截图](./images/photo1.jpg)
```

解析时以输入 Markdown 文件的父目录为基准路径，拼接相对路径得到绝对路径。

### 6.2 溢出处理

图片宽度撑满有效阅读区（max-width: 840px），高度按原始宽高比等比缩放，不超出页面边界。

### 6.3 图片与文字关系

图片作为行内块（inline-block），前后自动断行，形成独立段落参与分页容量计算。

---

## 7. 分页切割

### 7.1 切割策略

基于字符数的预计算方案：

1. 基于视觉常量（画布高度、边距、字号、行高、段落间距），计算单页最大可容纳字符数 N
2. 遍历 markdown-it 输出的 token 树，累加字符数
3. 达到容量上限时，在当前节点边界执行强制截断

### 7.2 安全闭合机制

若截断点位于复合标签内部（如加粗 `**`、斜体 `*`、代码块 `` ``` `` 等），执行以下操作：

- **当前页末尾**：自动补全闭合标签，确保 HTML 结构完整
- **下一页开头**：自动生成对应的起始标签，保证后续内容渲染正确

### 7.3 上限策略

无限制，完整输出所有内容。

---

## 8. 输出

- **格式**：PNG 图片，1080×1440px
- **命名规则**：`01_cover.png`, `02_content.png`, `03_content.png` ...（固定 2 位序号，前缀 0）
- **目录**：用户传入 `outputDir` 参数，图片写入该目录
- **无页码、无水印**

---

## 9. 目录结构

```
writing-to-card/
├── SKILL.md                    # 工作流编排层，唯一 LLM 调用层
├── references/                 # 知识固化层
│   ├── cover-template.html      # 封面 HTML 模板（Handlebars）
│   └── content-template.html    # 正文 HTML 模板（Handlebars）
├── templates/                   # 模板资产层（与 references/ 等效，本规范允许并存）
├── data/                        # 数据资产层（可选，MVP 暂不需）
├── evals/                       # 评估层
│   └── *.test.ts                # trigger eval / workflow eval
└── scripts/                     # 原子执行层
    ├── split.ts                  # 分页切割逻辑（AST 遍历 + 字符数计算）
    ├── renderer.ts               # Playwright 渲染 + 截图
    └── types.ts                  # 类型定义
```

**分层约束**：
- SKILL.md 是唯一可以发起 LLM 调用的层级
- scripts/ 不含任何 LLM 调用或自然语言生成逻辑
- 所有 prompt 和模板文本固化在 references/

---

## 10. 触发方式

用户通过自然语言调用 Skill，例如：
- "把 README.md 转成小红书卡片"
- "将下面的文章生成分享图片"
- 传入 title、subtitle（可选）、content（Markdown 字符串或文件路径）

SKILL.md 负责解析参数、编排流程、生成并写入文件。
