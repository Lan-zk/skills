WHY 写作自检系统

======================================================================
L1：硬性扫描
======================================================================

[ ] 高频踩雷词零命中（“说白了”“意味着什么”“本质上”“换句话说”“不可否认”）
    修复方向：不要替读者下结论，把结论改成更准确的问题或判断。

[ ] 没有教科书式时代开头
    修复方向：从一个具体场景、具体现象、具体矛盾切入。

[ ] 工具名和对象名足够具体
    修复方向：删掉“AI 工具”“某个模型”这类泛称，写具体名字。

[ ] 没有解释腔堆积
    修复方向：连续出现冒号、定义句、讲解句时，检查是不是已经从“陪读者想”滑成“给读者讲”。

======================================================================
L2：节奏与段落检查
======================================================================

[ ] 默认主线清楚，是在下潜，不是在打转
    常见失败原因：每段都在围着同一个问题换说法，没有明显的更深一层。

[ ] 每一段至少完成一次认知动作
    可接受动作：
    - 拆默认前提
    - 改写问题
    - 重写定义
    - 连接到更深核心
    - 从核心打开新可能

[ ] 没有伪推进段落
    伪推进的典型特征：
    - 再问一次，但没更深
    - 换词重复
    - 信息增加了，理解没移动

[ ] 发散回来后，主线更深了
    常见失败原因：中途联想到别处很精彩，但回来之后只是重复原命题。

[ ] 排版服务节奏，而不是制造碎片感
    常见失败原因：大量单句成段、问句成段、判断成段，把文章切成思维碎片。

[ ] 标题数量和层级足够克制
    常见失败原因：每一次局部转折都起标题，把文章排成说明书。

[ ] Markdown 结构没有喧宾夺主
    常见失败原因：列表太多、横线太多、加粗太多，阅读感从“陪读者想”滑成“给读者汇报”。

======================================================================
L3：深度检查
======================================================================

[ ] 找到了默认前提，而不是只找到一个观点
    修复方向：问自己，“支撑这个观点成立的默认前提是什么？”

[ ] 说明了前提为什么不稳，而不是只说它存在
    修复方向：补上现实变化、语境变化、角色变化或技术变化。

[ ] 前提被掀开后，对象真的被重新理解了
    修复方向：补一句新的定义。不要只写“问题更复杂了”。

[ ] 代价或外溢影响被点到
    修复方向：至少写清这个前提变化会影响谁、影响什么边界。

[ ] 没有知识堆砌淹没主线
    修复方向：如果一个段落里塞了多个事实，但没有推动主线，就删。

[ ] 版式选择和内容动作匹配
    修复方向：对照、分级、步骤才用列表；关键判断才加粗；旧前提才用引用块。

======================================================================
L4：终审
======================================================================

终审问题 1：

读完之后，读者得到的是“信息更多了”，还是“站的位置变了”？

如果只是信息更多了，这篇文章大概率还是局部解释文，不是强 WHY。

终审问题 2：

删掉任意一段，主线是否会失去一个认知台阶？

如果不会，这一段大概率是冗余。

终审问题 3：

这篇文章掀开的前提，能不能用一句话说清？

如果不能，说明作者自己还没真正抓到地基。

======================================================================
快速通道：2 分钟自检
======================================================================

步骤 1（30 秒）
用 Ctrl+F 搜五个高频踩雷词。命中即重写整句。

步骤 2（30 秒）
看每一段，问一句：这一段让主线更深了吗？如果没有，删或并。

步骤 3（30 秒）
找到全文第一次真正进入前提层的位置。如果找不到，说明还没挖进去。

步骤 4（30 秒）
看结尾。它是在宣布答案，还是把读者留在一个更值得继续想的问题上？

步骤 5（30 秒）
扫一遍 Markdown 结构。问自己：如果去掉这些标题、列表、横线、加粗，文章的主线会不会更清楚？如果答案是会，说明结构用多了。
