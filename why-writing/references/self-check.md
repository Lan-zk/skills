WHY 写作返工与终审清单

这份文件默认只在两种情况下使用：

- 成稿后，做返工和终审
- 卡住时，回头定位是哪一层出了问题

默认理解：

- L1 只保留少量高收益的硬扫项，用来拦明显失真
- L2 和 L3 主要检查主线、节奏、作者底色和认知动作
- L4 是终审提问，用来校正文气和重心，不是用来机械扣分

不要在起稿前或起稿中逐条核对这份清单。
起稿阶段真正优先的，应该是作者底色、文气方向和主线下潜，而不是局部排雷。

如果一篇文章只是通过了很多局部检查，却仍然没有作者重力场、没有问题改写、没有真实气压，那它仍然不是好的 WHY。

======================================================================
L1：硬性扫描
======================================================================

[ ] 高频踩雷词零命中（“说白了”“意味着什么”“本质上”“换句话说”“不可否认”）
    修复方向：不要替读者下结论，把结论改成更准确的问题或判断。

[ ] 没有教科书式时代开头
    修复方向：从一个具体场景、具体现象、具体矛盾切入。

[ ] 工具名和对象名足够具体
    修复方向：删掉“AI 工具”“某个模型”这类泛称，写具体名字。

[ ] 没有解释腔堆积
    修复方向：连续出现冒号、定义句、讲解句时，检查是不是已经从“陪读者想”滑成“给读者讲”。

[ ] 没有“词先显眼，问题后出现”的刻意句
    修复方向：如果一个词先让你意识到“这句写得很用力”，而不是先把你带进问题，换成更自然的说法。

======================================================================
L2：节奏与段落检查
======================================================================

[ ] 默认主线清楚，是在下潜，不是在打转
    常见失败原因：每段都在围着同一个问题换说法，没有明显的更深一层。

[ ] 每一段至少完成一次认知动作
    可接受动作：
    - 拆默认前提
    - 改写问题
    - 重写定义
    - 连接到更深核心
    - 从核心打开新可能

[ ] 没有伪推进段落
    伪推进的典型特征：
    - 再问一次，但没更深
    - 换词重复
    - 信息增加了，理解没移动

[ ] 发散回来后，主线更深了
    常见失败原因：中途联想到别处很精彩，但回来之后只是重复原命题。

[ ] 排版服务节奏，而不是制造碎片感
    常见失败原因：大量单句成段、问句成段、判断成段，把文章切成思维碎片。

[ ] 标题数量和层级足够克制
    常见失败原因：每一次局部转折都起标题，把文章排成说明书。

[ ] Markdown 结构没有喧宾夺主
    常见失败原因：列表太多、横线太多、加粗太多，阅读感从“陪读者想”滑成“给读者汇报”。

[ ] 作者站位清楚，文章不是在替素材代言
    常见失败原因：素材是什么观点，文章就是什么观点，作者像被抹平了。

[ ] 至少有一处私人视角连接句，让人知道作者为什么偏偏会卡在这里
    常见失败原因：有判断，没有作者位置，读起来像无主语的聪明文章。

[ ] 前几段有阅读牵引力，读者能被快速拉进主问题
    常见失败原因：道理是对的，但开头太平，进入主问题太慢。

[ ] 粗粝感来自真实判断，不是来自口癖装饰
    常见失败原因：故意加语气词、断句、口头禅，表面像真人，实际更像模型在演。

[ ] 思考过程主要露在关键转折处，而不是全篇都在表演笨拙
    常见失败原因：为了去 AI 味，把整篇都写散了。

[ ] 口语化是自然推进，不是在模仿某种现成腔调
    常见失败原因：借了 khazix 的表皮，没有借到他的阅读牵引力。

[ ] “我们”没有被拿来预先绑定读者站位
    常见失败原因：作者和读者在文本里被提前绑成同一立场，削弱了主观判断本应保留的开放性。

[ ] 没有靠“第一层/第二层/更深层”这类词显性推读者
    常见失败原因：层级本来可以通过推进被感受到，结果被提示词硬说出来，读感会突然变得很程序化。

[ ] 至少有一处先把对立面讲顺，再切自己的判断
    常见失败原因：急着拆旧解释，导致后面的改写显得轻飘。

======================================================================
L3：深度检查
======================================================================

[ ] 找到了默认前提，而不是只找到一个观点
    修复方向：问自己，“支撑这个观点成立的默认前提是什么？”

[ ] 说明了前提为什么不稳，而不是只说它存在
    修复方向：补上现实变化、语境变化、角色变化或技术变化。

[ ] 前提被掀开后，对象真的被重新理解了
    修复方向：补一句新的定义。不要只写“问题更复杂了”。

[ ] 代价或外溢影响被点到
    修复方向：至少写清这个前提变化会影响谁、影响什么边界。

[ ] 没有知识堆砌淹没主线
    修复方向：如果一个段落里塞了多个事实，但没有推动主线，就删。

[ ] 版式选择和内容动作匹配
    修复方向：对照、分级、步骤才用列表；关键判断才加粗；旧前提才用引用块。

[ ] 作者的职业位置、经验或价值排序真的进入了论证
    修复方向：用一句话说清“我为什么会从这里起疑”，不要只把作者当背景板。

[ ] 没有连续的概念打包句
    修复方向：如果连续出现“这不是 A，而是 B”“它重新定义了”“它本质上是”，删掉一两句，补对象和动作。

[ ] 结尾没有故作余味的尾句
    修复方向：如果最后一句单拎出来像姿态、像感叹、像硬留后劲，优先删掉或改成自然落回对象。

[ ] 结尾段不是在僵硬回收前文
    修复方向：标题本身不是问题。问题是结尾如果只把前面已经成立的判断再说一遍，优先删掉整段，而不是改标题。

======================================================================
L4：终审
======================================================================

终审问题 1：

读完之后，读者得到的是“信息更多了”，还是“站的位置变了”？

如果只是信息更多了，这篇文章大概率还是局部解释文，不是强 WHY。

终审问题 2：

删掉任意一段，主线是否会失去一个认知台阶？

如果不会，这一段大概率是冗余。

终审问题 3：

这篇文章掀开的前提，能不能用一句话说清？

如果不能，说明作者自己还没真正抓到地基。

终审问题 4：

把作者名字拿掉，换一个人来写，这篇文章还会不会几乎一样？

如果会，说明作者锚点还不够硬。

终审问题 5：

主标题是不是短、准、贴题，而且不会一眼看上去像通用 AI 标题？

如果不是，先重写标题，再回头看正文是不是也写虚了。

终审问题 6：

这个标题如果用了“还是不是”式追问，正文真的打到了对象边界吗？

如果没有，就换标题，不要拿句式冒充深度。

终审问题 7：

这篇文章是不是更口语了，但又还保得住 WHY 的骨架？

如果口语上去了，主线却松了，说明借过头了。

终审问题 8：

这篇文章读起来像是“作者正在想通”，还是“模型已经想完了”？

如果更像后者，去找那些太会命名、太会收束、太会把段落包漂亮的地方。

终审问题 9：

有没有某个词、某句话先把“写作姿态”推到前面，而不是先把问题推到前面？

如果有，优先改词，不要急着改结构。

终审问题 10：

文中的“我们”是真的必要，还是在替作者和读者提前结盟？

如果删掉“我们”后句子仍然成立，默认删。

终审问题 11：

文章里有没有靠“第一层”“第二层”“更深层”来提示推进，而不是让推进自己发生？

如果有，优先把这些提示词删掉，再看主线是否其实更顺。

终审问题 12：

结尾是不是像另起一段“写在最后”，把前文又摘要了一遍？

如果是，默认整段删掉再读一次。

======================================================================
快速通道：2 分钟自检
======================================================================

步骤 1（30 秒）
用 `Ctrl+F` 搜五个高频踩雷词。命中即重写整句。

步骤 2（30 秒）
看每一段，问一句：这一段让主线更深了吗？如果没有，删或并。

步骤 3（30 秒）
找到全文第一次真正进入前提层的位置。如果找不到，说明还没挖进去。

步骤 4（30 秒）
看结尾。它是在宣布答案，还是把读者留在一个更值得继续想的问题上？

步骤 5（30 秒）
扫一遍 Markdown 结构。问自己：如果去掉这些标题、列表、横线、加粗，文章的主线会不会更清楚？如果答案是会，说明结构用多了。

步骤 6（30 秒）
只看标题。问自己：它钉住的是这篇文章真正改写的问题，还是一个谁都能套的泛主题？
