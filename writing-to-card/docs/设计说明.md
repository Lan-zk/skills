# 设计方案

## 1. 技术栈与架构
* **渲染引擎**：采用 Node.js 后端服务，结合无头浏览器（Puppeteer 或 Playwright）将 HTML 渲染为图片并截图，确保排版的高度稳定性和精确度。
* **解析方案**：先将 Markdown 文本解析为 AST（抽象语法树），而非直接转换为 HTML 字符串，为安全的文本截断提供基础。

## 2. 核心参数与视觉规范 (MVP版)
* **画布尺寸**：1080 × 1440 像素（小红书标准 3:4 比例）。
* **背景设计**：采用纯色背景（首页与正文模板分开定义底色）。
* **字体设定**：优先调用系统级衬线体（"Songti SC", "SimSun", "Times New Roman", serif）。
* **正文排版**：
  * 左右边距（Padding）：120px（有效阅读区宽度 840px）。
  * 正文字号（Font Size）：44px。
  * 行高（Line Height）：1.8倍。
  * 段落间距（Margin Bottom）：80px。
  * 列表缩进：0px（顶格排版）。
* **封面排版**：主标题字号 110px - 120px，加粗，居中展示。

## 3. 运行管线 (Pipeline)

**阶段一：输入与元数据提取**
* 系统接收两个独立参数：`title`（首页标题）与 `content`（正文 Markdown）。
* 若未显式提供 `title`，系统默认提取输入文件的文件名作为封面标题。

**阶段二：预计算与 AST 切割**
* 基于预设的视觉常量（分辨率、边距、字号、行距），数学计算出单页最大能容纳的字符数或节点容量 $N$。
* 在 AST 层面进行遍历与字数累加。达到容量上限时执行**强制打断**。
* **安全闭合机制**：若截断点位于加粗、斜体或代码块等闭合节点内部，系统将在当前页末尾自动补全闭合标签，并在下一页开头自动生成对应的起始标签，确保渲染层面 HTML 结构的绝对完整性。

**阶段三：模板装配**
* 将提取的 `title` 注入“首页 HTML 模板”。
* 将切割好的 AST 分段转换为 HTML 片段，依次注入“正文 HTML 模板”。

**阶段四：渲染与输出**
* 启动无头浏览器，加载各页面 HTML 结构并执行精确截图。
* 按照序列顺序输出图片文件，命名规则示例：`01_cover.png`, `02_content.png`, `03_content.png`。
