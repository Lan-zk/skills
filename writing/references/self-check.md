本文档为跨模式通用质检清单，why-deep 专属检查项见 `modes/why-deep.md`。

======================================================================
L1：硬性扫描
======================================================================

[ ] 踩雷词零命中——对照 `anti-ai-patterns.md` 第 1 类逐词扫描
    修复方向：命中即重写整句。不要替读者下结论，把结论改成更准确的问题或判断。

[ ] AI 句式零重复——对照 `anti-ai-patterns.md` 第 2 类，同一句式全文最多一次
    修复方向：拆成短句，用多样化表达。

[ ] 没有概念打包——对照 `anti-ai-patterns.md` 第 3 类
    修复方向：把打包句拆开，先说具体看到了什么，再让判断析出。

[ ] 没有教科书式时代开头
    修复方向：从一个具体场景、具体现象、具体矛盾切入。

[ ] 工具名和对象名足够具体
    修复方向：删掉"AI 工具""某个模型"这类泛称，写具体名字。

[ ] 没有解释腔堆积
    修复方向：连续出现冒号、定义句、讲解句时，检查是不是已经从"陪读者想"滑成"给读者讲"。

[ ] 没有"词先显眼，问题后出现"的刻意句——对照 `anti-ai-patterns.md` 第 9 类
    修复方向：如果一个词先让你意识到"这句写得很用力"，而不是先把你带进问题，换成更自然的说法。

[ ] 没有同义词轮换——对照 `anti-ai-patterns.md` 第 11 类
    修复方向：同一个对象如果名字变了，确认读者不需要回头猜"这是同一个东西吗"。精确的重复好过模糊的变化。

[ ] 没有凑数的三连排比——对照 `anti-ai-patterns.md` 第 12 类
    修复方向：三个并列里如果删掉一个意思完全不变，就删掉那个。

[ ] 引用权威时有具体出处——对照 `anti-ai-patterns.md` 第 13 类
    修复方向："业内人士认为""有研究显示"这类模糊引用，要么写具体（谁、什么时候、在哪），要么改成自己的判断。

[ ] 粗体使用克制，没有"粗体标题+冒号"的列表格式
    修复方向：粗体只在真正需要强调时使用；列表项开头不要用 `**标题:** 内容` 的模板格式，改成自然叙述或简短列表。

======================================================================
L2：节奏与段落检查
======================================================================

[ ] 每一段有实质推进，不是换词复述
    常见失败原因：每段都在围着同一个问题换说法，信息增加了，理解没移动。

[ ] 没有伪推进段落
    伪推进的典型特征：
    - 再问一次，但没更深
    - 换词重复
    - 信息增加了，理解没移动

[ ] 没有空泛大词——对照 `anti-ai-patterns.md` 第 6 类
    常见失败原因："显著提升""许多""越来越"等词不给具体数字和对象。

[ ] 排版服务节奏，而不是制造碎片感
    常见失败原因：大量单句成段、问句成段、判断成段，把文章切成思维碎片。

[ ] 标题数量和层级足够克制
    常见失败原因：每一次局部转折都起标题，把文章排成说明书。

[ ] Markdown 结构没有喧宾夺主
    常见失败原因：列表太多、横线太多、加粗太多，阅读感从"陪读者想"滑成"给读者汇报"。

[ ] 没有靠层级宣告硬推读者——对照 `anti-ai-patterns.md` 第 7 类
    常见失败原因：层级本来可以通过推进被感受到，结果被提示词硬说出来，读感会突然变得很程序化。

[ ] 没有态度中立/安全段落——对照 `anti-ai-patterns.md` 第 8 类
    常见失败原因：在需要判断的地方拒绝判断，"既有优点也有缺点""具体取决于实际情况"。

[ ] 粗粝感来自真实判断，不是来自口癖装饰
    常见失败原因：故意加语气词、断句、口头禅，表面像真人，实际更像模型在演。

[ ] 思考过程主要露在关键转折处，而不是全篇都在表演笨拙
    常见失败原因：为了去 AI 味，把整篇都写散了。

[ ] 口语化是自然推进，不是在模仿某种现成腔调
    常见失败原因：借了某种文风的表皮，没有借到它的阅读牵引力。

[ ] 不是"干净但无灵魂"——对照 `anti-ai-patterns.md` 第 10 类
    常见失败原因：去掉 AI 味之后变成了安全、正确、但没有人在里面的白开水。检查是否有至少一处是"你"在场的证据——真实的认知冲突、不适感、被说服的过程。

[ ] 没有翻译腔——对照 `anti-ai-patterns.md` 第 5 类
    常见失败原因："进行 + 动词""通过 X 来 Y"、嵌套从句、被动句式过多。

[ ] 结尾没有故作余味的尾句——对照 `anti-ai-patterns.md` 第 4、9 类
    修复方向：如果最后一句单拎出来像姿态、像感叹、像硬留后劲，优先删掉或改成自然落回对象。

[ ] 结尾段不是在僵硬回收前文
    修复方向：如果结尾只是把前面已经成立的判断再说一遍，优先删掉整段，而不是改标题。

======================================================================
L3：结构与版式检查
======================================================================

[ ] 版式选择和内容动作匹配
    修复方向：对照、分级、步骤才用列表；关键判断才加粗；旧前提才用引用块。

[ ] 没有连续的概念打包句
    修复方向：如果连续出现"这不是 A，而是 B""它重新定义了""它本质上是"，删掉一两句，补对象和动作。

[ ] 发散段落回来后，主线更深了，而不是原地重复
    常见失败原因：中途联想到别处很精彩，但回来之后只是重复原命题。

[ ] 作者的职业位置、经验或价值排序真的进入了论证
    修复方向：用一句话说清"我为什么会从这里起疑"，不要只把作者当背景板。

======================================================================
L4：终审
======================================================================

终审问题 1：

读完之后，读者得到的是"信息更多了"，还是"真正理解变了"？

终审问题 2：

删掉任意一段，主线是否会失去一个认知台阶？

如果不会，这一段大概率是冗余。

终审问题 3：

把作者名字拿掉，换一个人来写，这篇文章还会不会几乎一样？

如果会，说明作者锚点还不够硬。

终审问题 4：

主标题是不是短、准、贴题，而且不会一眼看上去像通用 AI 标题？

如果不是，先重写标题，再回头看正文是不是也写虚了。

终审问题 5：

这篇文章是不是更口语了，但又还保得住骨架？

如果口语上去了，主线却松了，说明借过头了。

终审问题 6：

这篇文章读起来像是"作者正在想通"，还是"模型已经想完了"？

如果更像后者，去找那些太会命名、太会收束、太会把段落包漂亮的地方。

终审问题 7：

有没有某个词、某句话先把"写作姿态"推到前面，而不是先把问题推到前面？

如果有，优先改词，不要急着改结构。

终审问题 8：

文中的"我们"是真的必要，还是在替作者和读者提前结盟？

如果删掉"我们"后句子仍然成立，默认删。

终审问题 9：

结尾是不是像另起一段"写在最后"，把前文又摘要了一遍？

如果是，默认整段删掉再读一次。

终审问题 10：

把文章里的判断都拿掉，换成中性陈述，这篇文章还剩什么？

如果答案是"结构、信息、排版都还在"，说明判断缺席——文章是干净的，但没有灵魂。回去找一个你真正被卡住、被触动、或想反驳的地方，把判断补上。

======================================================================
快速通道：2 分钟自检
======================================================================

步骤 1（30 秒）
用 `Ctrl+F` 搜五个高频踩雷词。命中即重写整句。

步骤 2（30 秒）
看每一段，问一句：这一段让理解更深了吗？如果没有，删或并。

步骤 3（30 秒）
扫一遍 Markdown 结构。问自己：如果去掉这些标题、列表、横线、加粗，文章的主线会不会更清楚？如果答案是会，说明结构用多了。

步骤 4（30 秒）
只看标题。问自己：它钉住的是这篇文章真正要改写的问题，还是一个谁都能套的泛主题？

步骤 5（30 秒）
看结尾。它是在宣布答案，还是把读者留在一个更值得继续想的问题上？

步骤 6（30 秒）
扫一遍"我们""第一层""第二层"这类提示词。如果它们不是对象本身的词，默认删掉再读。
